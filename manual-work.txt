状態: [x] 完了(2026-08-15 実施)✅
  実施内容:

   - Functions: awardPointsOnPost 作成 / validateCouponV3 削除

   - Firestore rules: firestore.rules を本番反映(構文コンパイルOK)
  → デプロイ後の本番動作確認(下記「デプロイ後の確認」)はユーザーにて実施をお願いします。

内容:
  Phase 2(セキュリティ)と Phase 3(データ整合性)の実装はコミット・push 済みだが
  本番未反映。以下は必ず「同時に」反映する(バラバラだと投稿が壊れるため)。

  理由(同時反映が必須):
   - 新ルールは users.points 等のクライアント書込を禁止する。旧フロントのままだと
     reviews.js が points をクライアント書込しようとして投稿が失敗する。
   - よって「新フロント(Hosting)」「新ルール」「ポイント付与Functions」は一括反映が必要。

  手順:
   1) npm run build
   2) firebase deploy --only hosting,firestore:rules,functions --project nukebuy
      ※functions デプロイ時、削除される関数(validateCouponV3)の確認プロンプトに注意
        (必要なら --force)。ext-firestore-stripe-payments-* は拡張管理のため影響なし。

  デプロイ後の確認(本番):
   - Web: ログイン → 報告投稿 → ポイント付与表示(15〜25pt) → 検索でヒット
   - users.points をクライアントから書き換えられないこと(投稿は正常に通ること)

  ロールバック:
   - ルールを戻す場合は firestore.rules.production-backup-2026-08-14 の内容を
     firestore.rules に戻して再デプロイ。

M-2. Chrome拡張の実機テスト(認証・posts統一の確認)
============================================================
状態: [ ] 未実施(M-1 デプロイ後に実施)

内容:
  Work 2-5 で拡張に認証を実装し、報告の保存先を posts に統一した。
  ※当開発環境では Chrome 拡張を実行できないため、ユーザーによる実機テストが必要。

  手順:
   1) chrome://extensions を開く → デベロッパーモード ON
   2) ヌケバイ拡張を「更新(再読み込み)」する(vendor/ 同梱・manifest 0.2.0 反映のため)

   5) Web 側の検索で、その動画IDが報告件数に反映されているか確認
   6) ログアウト → 未ログイン時はログインフォームが出ることを確認

  期待結果:
   - 未認証だった旧拡張(extension_reports・ルールで全拒否)から、
     認証付きで posts に保存され、Web 検索に反映される状態になる。
