# ヌケバイ 修正案 (2026-08-14 作成)

本ドキュメントは、コードベース全体(src/, functions/, chrome-extension/)を調査した上で、
「自分ならこういう仕様にする」という観点でまとめた修正提案である。

=====================================================================
1. 現状のアーキテクチャと調査サマリ
=====================================================================
- フロント: Vue 3 (Composition API) + Vite + Pinia + Vue Router
- バックエンド: Firebase (Auth / Firestore / Hosting / Cloud Functions asia-northeast1)
- 決済: Stripe(pk_liveキーをフロントにハードコード) + PayPal(未完成・認証情報プレースホルダ)
- 付随物: Chrome拡張(未認証でFirestoreへ直接投稿)、テスト用HTML、各種ログファイルがリポジトリ直下に混在

主要データ:
- posts: 報告(videoId, videoTitle, reasons[], authorId, createdAt, source)
- users: プロフィール(points, reportCount, searchCount, role, subscriptionStatus)
- customers/{uid}/subscriptions: サブスク情報(クライアントから直接作成している)
- products/{id}/prices: 料金プラン

=====================================================================
2. あるべき仕様(提案)
=====================================================================

--- 2.1 コア価値の再定義 -----------------------------------------
このサービスの価値は「動画IDで検索すると、その動画が『ヌけない』と報告された
件数と理由の内訳が見られる」こと。したがって最優先は:
  (a) 報告データの信頼性(不正・重複・表記ゆれの排除)
  (b) 検索のヒット率(正規化した videoId による確実なマッチ)
  (c) データを守るセキュリティ(ルールなしの現状は致命的)
UI改善や課金より先にこの3点を固めるべき。

--- 2.2 videoId の正規化仕様(最重要) ----------------------------
現状: 投稿(ReviewForm)は入力のまま保存、検索(Search)は完全一致、
Chrome拡張は小文字化して保存。→ 同じ動画が別IDとして散らばり検索に出ない。

提案仕様:
- 共通ユーティリティ src/utils/videoId.js を新設し、投稿・検索・拡張の全経路で使用
- 正規化ルール: 全角→半角、大文字化(品番は慣習的に大文字)、前後空白除去、
  区切りは「ABCD-123」形式にハイフン統一(「abcd123」「ABCD 123」も同一視)
- 保存時は正規化済み videoId のみ保存。検索時も正規化してから照会
- 既存データはマイグレーションスクリプトで正規化(Functions or 管理スクリプト)

--- 2.3 報告(レビュー投稿)仕様 ---------------------------------
- 報告理由マスタは stores/reasons.js に一本化。Search.vue 内の重複マップ
  (reasonDisplayMap)は削除し、ストアから引く(現状 BAD_CAMERA が検索側に無く不整合)
- 同一ユーザー×同一動画の重複チェックは現状のクエリ方式でよいが、
  正規化後の videoId で行う
- ポイント付与はクライアントで users を updateDoc する現方式を廃止し、
  Cloud Functions(onCall もしくは posts onCreate トリガー)でサーバー側付与に変更。
  乱数ポイント(15〜25)もサーバーで決定
- videoTitle は必須のままでよいが、文字数上限(例:100字)とtrimを入れる

--- 2.4 検索仕様 -------------------------------------------------
- 正規化 videoId による完全一致(2.2 実施後はこれで十分機能する)
- 未ログイン: 1回まで(現状踏襲)。ただし localStorage だけでは簡単に回避される
  ことは許容し、「案内目的の制限」と割り切る(サーバー強制はコスト過大)
- ログイン済み: 無制限(現状踏襲)。searchCount はサーバー側でインクリメントし
  利用統計として保持
- 結果0件時に「最初の報告者になりませんか?」から報告フォームへ videoId を
  引き継いで遷移できる導線を追加(現状は文言のみでリンクなし)

--- 2.5 認証・年齢確認仕様 ---------------------------------------
- アダルトサービスなので年齢確認ゲートは必須。現状ルーターガードから削除されて
  いる(AgeVerification.vue は存在するが未使用)。
  提案: 初回訪問時にモーダルまたは専用ページで確認し localStorage に記録、
  未確認なら全ページで確認を挟む(router.beforeEach 復活)
- ログイン: 現状の Email/Password + Google でよい。パスワードリセット導線が
  無いので Login ページに「パスワードを忘れた場合」を追加
- ルーターガードの user/store 同期問題(router/index.js の警告コメント部分)は、
  App.vue の onAuthStateChanged 完了を単一の Promise で待つ形に整理する

--- 2.6 ポイント仕様 ----------------------------------------------
- 付与: サーバー側(2.3)。用途: 現状「近日実装予定」のまま。
  提案: 当面は「貯まる」だけと明記し、UserProfile の「ポイントを利用する」
  ボタン(準備中アラートのみ)は非表示にして期待値のズレを防ぐ
- 将来サブスク割引に使う場合は Stripe/PayPal のクーポン発行と連動させる

--- 2.7 課金仕様(要ユーザー判断) -------------------------------
現状: Stripeが使えなくなり一般利用延期(コミットログより)。PayPal実装は
認証情報プレースホルダ・依存パッケージ未導入・Webhookが onCall(誤り)で未完成。
ContractManagement.vue は存在しない Functions(getSubscriptionDetails,
cancelSubscription, reactivateSubscription, applyCouponToSubscription)を呼ぶ。

提案(方針A: 課金凍結 ※推奨):
- 当面は全機能無料で公開し、課金関連ページ(/subscription, /contract-management,
  /success)への導線を隠す。決済コードは feature flag で無効化
- ユーザー数が付いてから決済プロバイダを再選定(アダルト可のプロバイダ:
  PayPal(規約要確認)/CCBill/Epoch/銀行振込等)

提案(方針B: PayPal完成):
- Secret Manager で認証情報管理、Webhook を onRequest + 署名検証で実装、
  サブスク作成をサーバー経由に変更、解約系 Functions を新規実装
- 工数が大きいので方針Aの後段フェーズとするのが現実的

いずれの場合も、Subscription.vue の「Firestoreに商品が無い時にテスト用プランを
表示して購入させる」フォールバックは即時削除すべき(偽の購入導線)。

--- 2.8 セキュリティ仕様(最優先) -------------------------------
- firestore.rules をリポジトリに追加し firebase.json に登録。最低限:
  * posts: 読み取り公開 / 作成はログイン済みかつ authorId == auth.uid、
    スキーマ検証(videoId形式, reasons はマスタコード配列, 文字数上限)/
    更新・削除は本人 or admin のみ
  * users: 本人のみ読み書き。ただし points, role, subscriptionStatus は
    クライアントから書き込み不可(Functionsのみ)
  * customers/**: クライアント書き込み禁止(決済はサーバー経由に統一)
  * products/prices: 読み取りのみ
- Chrome拡張の未認証投稿は廃止(ルール上も塞がれる)。拡張は将来
  Firebase Auth を組み込むまで投稿機能を停止 or Webへ誘導する形に変更
- Firebase構成のAPIキー公開自体は問題ないが、ルールが唯一の防壁であることを
  README に明記
- functions の Stripe/PayPal キーは Secret Manager(defineSecret) で管理

--- 2.9 コード品質・保守性仕様 -----------------------------------
- 壊れているコードの除去/修正:
  * userStore.incrementFreeUsage / freeUsageCount(存在しない)を参照する
    Home.vue / ReviewDetails.vue / ReviewCard.vue を修正
  * functions/index.js の STRIPE_KEY 未定義(validateCouponV3 は呼ぶと必ず落ちる)
  * services/paypal.js(未使用+依存欠落+import漏れ)は削除 or 完成
- デッドコード削除: HelloWorld.vue、Profile.vue(UserProfile.vueと重複)、
  test-coupon*.html、cascade_test_file.txt、deploy*.log、pglite-debug.log、
  Campaign.vue / Prerelease.vue(2025年で終了したキャンペーン)
- console.log の全面除去(グローバルルールでも禁止)
- 大きすぎるファイルの分割: Home.vue(1411行)、Subscription.vue(1106行)は
  セクション単位のコンポーネントに分割し、スタイルも整理(目安400行以下)
- ハードコードされたキャンペーン期間判定(router/index.js, user.js)を削除
- ESLint + Prettier 導入。テストは Vitest で store / utils から着手し、
  主要フロー(投稿・検索)の結合テストを追加

--- 2.10 UI/UX 仕様 ----------------------------------------------
- サイト名表記の統一: 「ヌケバイ」「NukeBye」「NukeBAI」「Nukebuy」が混在。
  日本語表記「ヌケバイ」/英字「NUKEBAI」に統一(要ユーザー確認)
- Home の「最大3回まで無料」等の文言が実装(未ログイン1回/ログイン無制限)と
  矛盾しているので実態に合わせて修正
- 検索結果ページ: 報告理由内訳を件数順に並べ、割合バー表示にする
- 404/エラー時の案内強化、ローディングのスケルトン化(任意)
- SEO: 動的な title/meta 設定(vueuse/head 等)、OGP追加(任意)
